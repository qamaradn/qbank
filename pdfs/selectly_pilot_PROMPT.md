## Context

admin (`qamar.adn@gmail.com`). We are about to run a **ten-form pilot** — 273 questions —

CSV a human carries back. Do not propose automating either direction.

## Your tasks, in order

**1. Merge and deploy `qbank_id`.**
Branch `feature/qbank-id-addressability` (commit `c52ffa9`) is local and unmerged. It adds
`questions.qbank_id`, makes `/api/questions/import` upsert on it, and lets
`/api/admin/questions-fix` address rows by it. Apply
`supabase/migrations/0001_add_questions_qbank_id.sql`. The code is already correct —
including that it deliberately keeps `active` out of the upsert's update set — so this is
merge, migrate, deploy, verify. Do not "improve" the upsert semantics; the comments explain
why they are what they are.

**2. Accept the form columns.** `formId`, `formPosition`, `formKind` appear nowhere in this
repo. qbank has been sending them on every question since forms were dealt, and zod strips
them silently. Add them to the `questions` table, to `validateQuestion`, and to the import's
values object (both the mcq and writing branches). Without this the reload produces
form-less questions and every form has to be dealt a second time. See handover §2 and §4.1.

**3. Add `qbank_id` to the flagged-questions CSV.**
`/api/admin/flagged-questions/export` currently emits `question_id`, which is Selectly's own
uuid. qbank has never seen it and cannot resolve it, so the reviewer's findings dead-end.
Join to `questions.qbank_id` and add the column. qbank's ingest tool refuses a CSV without
it. Handover §8.3. Small change, but the review loop is blocked on it.

**4. `form_attempts` and the two selector changes.** Fixed forms replace random selection,
and drill is timed at exact exam pace. Handover §2 and §3 specify the rules; §4.2 gives the
table. **VIC reading and verbal are ONE section in the 2026 paper**, so `vic-drill-rv-*`
forms mix both and a category-based selector cannot serve them — fetch by `form_id`.

**5. Rewrite `vic-seal` in `schools.ts`.** It still describes the pre-2026 exam: 4 sections,
120 minutes, written expression as one 25-minute task. The real paper is 3 components, 155
minutes, writing 2 tasks in 40 minutes. Forms are already dealt against the real paper, so
no VIC form can be served until this matches. Handover §4.1b and §4.1c.

**6. Wipe and reload — last, and only after 1–4 are deployed.**
Wipe `questions` and `question_flags` only. Not accounts, not school config, not the two
logins. Handover §1.1 explains why a wipe beats a backfill.

The flags currently in the admin are **spent** — already actioned in qbank, pointing at
uuids the reload will not preserve. Do not try to carry them forward or reconcile them.

Then tell the qbank side to push. It will run
`push_to_selectly.py --reset-tracking` followed by a `--forms` push of the ten pilot forms.
**The reset is mandatory**: qbank's tracking file still lists 5,321 questions as pushed, and
without clearing it the reload sends almost nothing.

  exception is `active`, which is a serving decision and belongs here.
